# 六号院 · 园区数字孪生

Vue 3 + TypeScript + Three.js 的可交互三维园区项目，配套可复现的 Blender 模型、Cycles 展示渲染和动画场景。位置范围依据用户提供的涿州平安小区六号院截图；国际部大楼、装备专业化大楼依据第二张标注图定位。

## 本地运行

需要 Node.js 22.12+（本项目使用 Node 24 验证）。

```sh
npm install
npm run dev
```

打开终端输出的 `Local` 地址。默认端口为 5173；若被占用，Vite 会自动尝试 5174、5175 等可用端口，不会因此退出。也可以用 `npm run dev -- --port 5180` 指定首选端口。页面运行不需要地图 API Key，不请求外部底图、字体或在线三维模型。

```sh
npm test
npm run build
npm run preview
```

生产文件位于 `dist/`，可以部署到普通静态服务器的站点根目录。不要直接以 `file://` 打开 HTML。

## 使用

- 左侧搜索建筑名或 OSM 编号，点击列表、三维建筑或标签飞行定位。
- 左键旋转、右键平移、滚轮缩放；右侧场景工具切换全园区、俯视、南侧办公区、梧桐树行道、昼夜和全屏。
- 图层开关控制树木、行人、车辆、标注、轨迹和 OSM 轮廓。
- “交通运行”展示车位占用，车辆完成出位、园路行驶、入位和停放过程。路径经过建筑轮廓避让检查。
- “触发模拟告警”产生当前时间事件，支持定位、确认、解除、回放。已记录的处理时间不会因为回看过去而被覆盖。
- 时间轴覆盖 09:00–09:15，支持播放、暂停、1/2/4/8 倍速及拖动。指标、人车位置、停车占用和告警状态由同一个模拟时间决定。
- 右上角信息按钮可查看数据来源、真实性范围及下载原始 OSM 文件。

## 真实性与数据来源

OSM 真实下载时间：**2026-09-20T07:38:09.767Z**（北京时间 15:38:09）。数据基准时间：**2026-09-20T07:36:35Z**。下载范围 `[南纬度, 西经度, 北纬度, 东经度]` 为 `[39.4831, 116.0206, 39.4890, 116.0298]`。原始响应包含 83 个要素，不代表 83 栋建筑。

原始数据与 SHA-256 保存在 `public/data/osm-2026-09-20.json` 和 `public/data/osm-provenance.json`。其中下载日期、OSM 数据日期、建筑编辑日期不是同一个概念。本项目未宣称所有建筑在当天测绘或更新。

联网搜索覆盖了六号院房产页面、东方物探相关建筑资料与图片搜索。用户随后提供了两栋重点楼的实景照片，已用于更新可见立面；第二张只展示入口局部，不能推断完整楼高和背面。不能承诺测绘级或照片级现场一致性。第三方资料仅作参考，不把其他园区照片冒充本院区，不将无再分发授权的照片作为模型贴图。具体来源见 `docs/research.md`。

## Blender 资产与动画

文件：

- `blender/build_campus.py`：完整场景生成脚本，读取同一份场地 JSON。
- `blender/residential_facades.py`：依据本次四张住宅照片生成六层住宅立面与原创程序化纹理。
- `blender/plane_trees.py`：依据梧桐树近照生成刷白树干、修剪分叉和密实树冠。
- `blender/campus.blend`：可编辑场景，含建筑、道路、梧桐树近似模型、灯光、相机和代表性人车动画。
- `public/models/campus.glb`：网页使用的静态园区资产。
- `public/models/vehicle.glb`、`pedestrian.glb`：网页使用的交通和行人资产。
- `blender/motion.json`：浏览器模拟器导出的代表性动画数据。
- `renders/campus-daylight.png`：Cycles 展示渲染输出。

使用 Blender 4.5 LTS 重建：

```sh
python scripts/prepare-campus.py
node --experimental-strip-types scripts/export-motion.ts
blender --background --python blender/build_campus.py
```

Blender 中为 Z 轴向上，网页为 Y 轴向上；脚本统一转换。动画时间范围为 1–21601 帧、24 fps，默认展示 09:02:00 对应的第 2881 帧。Blender 保留 8 辆行驶车辆和 12 名代表性行人的动画，网页实时运行 36 辆车和 270 名行人及骑行者。Blender 运动关键帧每 5 秒采样，转弯插值为演示近似；网页按路径距离实时求值。

GLB 使用原创程序化材质与生成纹理，不依赖外部图片素材。调整建筑时修改 `scripts/prepare-campus.py` 的输入参数并重新生成 JSON 与 Blender 资产，保持定位数据和模型一致。

住宅外墙、底层和屋面使用脚本生成的 PNG 纹理，来源是照片中的色彩与构件特征，并未把实景照片直接贴到立面。若只需更新网页中的住宅模型，可运行 `python scripts/update-residential-glb.py`；此脚本读取现有 `campus.glb` 并按 `blender/residential_facades.py` 替换 34 栋住宅的几何。要同步更新可编辑的 `campus.blend`，需安装 Blender 后重新运行完整场景生成脚本。当前仓库中的 `campus.blend` 仍是住宅与梧桐树修订前的快照。

若只需更新网页中的树木模型，可运行 `python scripts/update-tree-glb.py`；它读取同一份场地坐标，并按 `blender/plane_trees.py` 替换 GLB 中的 `Trees` 网格。两种资产更新脚本可重复运行，且不会改变建筑或树的位置。

重新下载 OSM：`npm run data:osm`。注意：脚本在本次交付中固定输出文件名；重新运行将覆盖该文件，来源记录仍会写入实际下载时间。若需要保留本次快照，请先备份或调整输出文件名。

## 实景立面修订

两栋重点楼已按用户补充照片更新：国际部采用竖向青绿玻璃、白色石材分格、挑檐及中英文标识；装备楼采用玻璃幕墙、金属装饰立柱、入口雨棚及蓝色中文标识。照片保存在 references，近景渲染在 renders/*-photo-guided.png，建模代码在 blender/photo_facades.py。照片中的临时车辆不属于建筑模型。

## 住宅实景修订（2026-09-29）

本次四张住宅照片用于修订 34 栋六层住宅的网页模型：将原先统一的尖屋顶改为照片中六层楼常见的低坡度屋面轮廓，外墙采用浅米白和旧奶油色变化，首层为赭色墙裙，加入楼层分缝、深色独立窗、部分防护栏、空调外机与排水管。单元入口采用蓝灰色门、赭红色雨棚与蓝色标牌。远景照片中的较低层红瓦住宅提供屋面色彩参考，但不据此修改现有 OSM 住宅的楼层数。照片位于 `docs/photo/`；未见立面与构件尺寸仍是近似重建。

## 梧桐树实景修订（2026-09-29）

行道树参照用户提供的近照改为截干修剪后的梧桐树：树基不规则刷白，主干更粗并有斑驳树皮，树冠下方可见粗短分叉与截枝，树叶组成横向舒展、深浅不一的密实冠层。右侧“梧桐树行道”视角可近景查看。首次树形修订预览见 `renders/plane-trees-photo-guided.png`。树龄、树高及每棵树的真实枝形仍属近似。

院区内南北向主路两侧补植 14 棵同款梧桐树，形成更连续的双排行道树；全场树位现为 304 个。补植位置按主路中心线与已有树距选取，避开建筑、车位及路口附近空间。树位由 `python scripts/prepare-campus.py` 生成，网页 GLB 可用 `python scripts/update-tree-glb.py` 更新；效果图见 `renders/main-road-plane-tree-rows.png`。

## 院区与厂房出入口调整（2026-10-05）

厂房只有两个东门，没有南门。厂房、装备专业化大楼与住宅区属于同一个共用院区；厂房院子西南出入口通过院内通道连向装备楼。国际部大楼有独立围界，其北侧出入口通过步行通道连向住宅区，南侧仍由原有引路通向范阳中路。围界、院门和新增通道的具体尺寸与位置为示意，尚未经测绘。使用 `python scripts/prepare-campus.py` 更新布局数据，再使用 `python scripts/update-compound-glb.py` 更新网页模型；完整 Blender 生成脚本调用同一份厂房与围界几何。厂房东门效果图见 `renders/factory-east-doors.png`。

## 厂房及院子实景修订（2026-10-07）

从北侧住宅楼朝南拍摄的厂房照片用于重建蓝色弧形压型钢板屋顶、浅色旧墙板、酒红色檐口、东侧两扇旧色门、窗和安全告示。厂房与装备楼之间的原简化通道改为混凝土地坪，加入羽毛球场线、五辆白色营房车（其中两处有绿色弧形遮棚）及蓝色周转箱。厂房没有南门，院子西南出入口继续连通装备楼。

`public/data/campus.json` 的 `factoryCourtyard` 记录示意范围、布置和照片来源。修改 `blender/campus_compounds.py` 后运行 `python scripts/update-compound-glb.py` 可更新网页模型；完整 Blender 生成脚本复用相同几何。照片只提供单个视角，场地尺寸、营房车数量及其精确位置按现有 OSM 建筑间距近似安排。

厂房周边的铁丝围栏依用户俯视截图红线重建：北侧、西侧、南侧及东南两段围栏形成示意边界，东南侧有一扇小门，西南侧留出通向装备楼的院区通道。红线未提供测绘坐标，折点和小门宽度按现有建筑轮廓近似定位；厂房南墙仍无门。围栏与小门数据记录在 `shared-yard.factoryFence`，网页 GLB 和完整 Blender 脚本复用同一几何。

## 厂房与住宅楼之间的通行修订（2026-10-07）

厂房、装备楼与南侧首排住宅之间不是一条贯通大路。厂房院内混凝土地坪从厂房北缘开始；楼间空隙不设置模拟行人或车辆。东侧模拟交通改走首排住宅北侧已有道路，西侧仍沿原有通道接入，保留厂房院子西南出入口与装备楼的连接。`trafficExclusionZones` 记录该空隙，自动化回放检查全程无人车进入。

## 国际部左侧人车清理（2026-10-07）

按从正门朝楼体看时的左右方向，国际部大楼西侧空地及正门左侧不再出现模拟行人或车辆。西侧停车区的模拟车辆已移除，保留的少量停放车辆使用住宅区北侧且不与建筑重叠的车位。国际部、厂房和装备专业化大楼南侧至范阳路北侧步行带之间的空地也不再投放模拟行人及骑行者；步行带上的人和范阳路上的骑行者仍保留。围界与北侧连接住宅区的出入口保持原位。回放测试检查这些区域全程无人车误入。

## 用户确认楼层修订

国际部大楼为 **20 层**，装备专业化大楼为 **6 层**。此项以用户最新确认为准，替代早期楼层估算。国际部高度暂按平均层高 3.6 m 估算为 72 m；装备楼高度暂沿用 25 m 估算。楼层数已确认并不代表建筑高度经过测量。模型、楼层分格、网页档案和独立 GLB 已同步更新。
